The premise is a Schelling point problem stated as a question instead of a diagram: if you and a stranger both had to be in Rochester tomorrow and couldn't communicate first, where would you go to find each other? A visitor drops a pin on a hand-drawn map, picks an arrival time, and says whether they've been to the city before. There's no tile provider and no map library underneath it — the map is a single SVG, drawn by hand, because the point was never geographic precision.

On submit, the new pin gets paired against exactly one prior pin, chosen uniformly at random, and that pairing is the headline result — not a heatmap, not a probability, one specific person's guess held up against yours. The aggregate view exists too: contours, an arrival-time distribution, the share of the map a pin would have caught. It sits below the match, deliberately, as a follow-up rather than the lead.

Street and landmark data for the base map came out of the Overpass API against OpenStreetMap, extracted once and hand-simplified rather than fetched live — there's no runtime dependency on Overpass at all, only a build-time script that produced the SVG in the first place. Pins themselves are Convex documents, and once placed, permanent; there's no edit or move path anywhere in the app, on purpose.
